# 이슈 #2: 술값을 마신 사람끼리 나누기

- 원본 이슈: https://github.com/dante01yoon/nbbang-factory-codex/issues/2
- 상태: 사람의 제품 결정 및 스펙 승인 대기
- 이 문서는 구현 제안이다. 아래 추천안은 승인 전까지 확정된 동작이 아니다.

## 사용자 문제

회식에 술을 마신 사람과 마시지 않은 사람이 함께 참석한다. 사용자는 음식 등 공통 비용은 모두에게 나누고, 술값은 마신 사람끼리만 나누어 각 사람이 낼 돈을 알고 싶다. 현재는 총 금액과 인원만 입력할 수 있어 술을 마시지 않은 사람도 같은 금액을 내게 된다.

## 제품 스펙

아래는 「사람이 정할 것」의 추천안을 승인했을 때의 화면과 동작이다.

### 입력과 결과

1. 기존 총 금액과 인원 입력을 유지한다. 총 금액은 술값을 포함한 실제 결제 금액이다.
2. `술값 따로 나누기` 선택을 추가한다. 기본은 꺼짐이며 기존 화면으로 시작한다.
3. 선택을 켜면 `총액에 포함된 술값` 입력과 사람별 `술 마심` 체크박스를 표시한다. 술값 초깃값은 0원, 체크박스 초깃값은 모두 해제다. 사람은 기존처럼 1번, 2번으로 구분한다.
4. 공통 비용은 `총 금액 - 술값`이다. 공통 비용은 전체 인원에게, 술값은 체크한 사람에게만 균등 배분한다. 마신 양에 따른 가중치는 이번 범위에 포함하지 않는다.
5. 각 사람의 결과에 공통 비용, 술값, 최종 낼 금액을 표시한다. 아래에 받은 돈 합계와 결제 금액을 표시한다. 유효한 입력에서는 합계가 결제 금액과 정확히 같아야 한다.
6. 인원을 늘리면 기존 번호의 선택은 유지하고 새 사람은 미선택으로 추가한다. 줄이면 사라진 번호의 선택을 제거하며, 다시 늘려도 그 선택을 복원하지 않는다.
7. 기능을 끄면 술값과 음주 선택을 초기화하고 전체 금액을 기존 `splitBill`로 계산한다. 기존 균등 분배의 잔액 동작을 바꾸는 작업은 별도 범위로 남긴다.

### 예시 계산

총 금액 120,000원, 전체 5명, 술값 30,000원, 1번과 3번만 음주:

- 공통 비용: 90,000원 ÷ 5명 = 각 18,000원
- 술값: 30,000원 ÷ 2명 = 음주자 각 15,000원

| 사람 | 공통 비용 | 술값 | 낼 금액 |
| --- | ---: | ---: | ---: |
| 1번 (음주) | 18,000원 | 15,000원 | 33,000원 |
| 2번 | 18,000원 | 0원 | 18,000원 |
| 3번 (음주) | 18,000원 | 15,000원 | 33,000원 |
| 4번 | 18,000원 | 0원 | 18,000원 |
| 5번 | 18,000원 | 0원 | 18,000원 |

받은 돈 합계와 결제 금액은 모두 120,000원이다.

### 원 단위 잔액과 오류

- 추천 잔액 규칙: 공통 비용과 술값을 각각 내림 나눗셈한 뒤, 각 비용의 나머지를 대상자의 번호 오름차순으로 1원씩 배분한다. 술값 잔액은 음주자에게만 배분한다.
- 예: 총액 10,001원, 술값 2,001원, 전체 3명, 2번·3번 음주. 공통 비용은 `[2667, 2667, 2666]`, 술값은 `[0, 1001, 1000]`, 최종 금액은 `[2667, 3668, 3666]`으로 합계 10,001원이다.
- 술값이 0원이면 음주자가 없어도 계산한다. 술값이 양수인데 음주자가 없으면 `술값을 나눌 사람을 선택해 주세요`를 표시한다.
- 술값이 총액보다 크면 `술값은 총 금액을 넘을 수 없습니다`를 표시한다.
- 금액은 0 이상의 안전한 정수, 인원은 1 이상의 안전한 정수여야 한다. 빈 입력, 소수, 음수, 유한하지 않은 값은 오류로 처리한다. 입력 도중 비어 있는 값을 0으로 확정하지 않는다.
- 오류가 있으면 기존 결과와 합계를 지우고 계산 안내를 표시한다. 잘못된 값을 수정하면 즉시 다시 계산한다.

## 기술 스펙

### 함수와 데이터 모양

- `src/split.js`: 기존 `splitBill(total, people)`, `sum(amounts)`, `won(n)`의 API를 유지한다. 새 순수 함수 `splitBillWithAlcohol({ total, alcoholTotal, drinkers })`를 추가한다.
- `drinkers`는 사람 번호 순서의 불리언 배열이며 길이가 전체 인원이다. 예시 입력은 `{ total: 120000, alcoholTotal: 30000, drinkers: [true, false, true, false, false] }`이다.
- 반환값은 사람 번호 순서의 `{ person, drinking, commonAmount, alcoholAmount, amount }[]`이다. 위 예시의 첫 항목은 `{ person: 1, drinking: true, commonAmount: 18000, alcoholAmount: 15000, amount: 33000 }`이다.
- 새 함수는 금액·인원·불리언 배열의 유효성을 확인하고, 공통 비용과 술값을 각각 배분한 뒤 합친다. `amount`는 두 비용의 합이고 모든 `amount`의 합은 `total`이어야 한다. 음주자가 없는 0원 술값은 별도 처리하여 0으로 나누지 않는다.
- 번호 배열을 받아 몫과 잔액을 배분하는 내부 함수를 두면 두 비용에 같은 규칙을 적용할 수 있다. 기존 `splitBill`에는 이 새 규칙을 적용하지 않는다.
- `src/app.js`: `render()`에서 기능 활성 상태에 따라 기존 함수 또는 새 함수를 호출한다. 음주 선택을 상태로 보관하고 인원 변경에 맞춰 배열을 조정한다. 입력 오류와 계산 오류를 표시하고, 새 결과의 `amount`를 `sum`으로 합산한다.
- `src/index.html`: 기능 선택, 술값 입력, 사람별 체크박스, 입력 오류 안내 영역을 추가한다. 각 체크박스에는 사람 번호를 포함한 레이블을 붙인다.
- `src/style.css`: 추가 입력과 비용 상세 내역을 작은 화면에서도 읽을 수 있도록 배치한다.
- 기존 `total`·`people` 쿼리 입력은 유지한다. 새 항목의 URL 공유, 사람 이름, 저장 기능은 이번 제안의 범위 밖이다.
- 예상 변경은 `src/`의 4개 파일이다. `factory:fix`의 2개 이하 조건에 해당하지 않으므로 승인 후 별도 기능 구현 작업으로 진행한다.

### 추가할 테스트와 검증

이 PR에서는 테스트를 작성하거나 기존 검증 기준을 수정하지 않는다. 향후 구현 시 아래 검증을 추가할 계획이며, 현재 하네스가 `test/`와 `*.test.*` 등을 보호하므로 테스트 파일 추가 권한이나 사람이 직접 추가하는 절차를 먼저 정해야 한다. 보호 설정을 에이전트가 수정하거나 우회하지 않는다.

| 검증 사례 | 기대 결과 |
| --- | --- |
| 위 120,000원 예시 | `[33000, 18000, 33000, 18000, 18000]` |
| 위 10,001원 잔액 예시 | `[2667, 3668, 3666]`, 술값은 비음주자에게 0원 |
| 1명, 총액 10,000원, 술값 3,000원, 음주 | 공통 7,000원 + 술값 3,000원 |
| 총액 0원, 술값 0원 | 모든 사람 0원, 음주 선택과 무관하게 유효 |
| 술값 0원, 음주자 없음 | 공통 비용만 전체에 배분 |
| 전원 음주 | 두 비용을 모두 전체에 배분, 합계 보존 |
| 총액 전부가 술값 | 공통 비용 0원, 음주자만 부담 |
| 양수 술값, 음주자 없음 | 계산 오류 |
| 술값 > 총액, 빈 입력, 음수, 소수, 안전하지 않은 정수 | 해당 입력 오류, 이전 결과 제거 |
| 빈 배열 또는 불리언이 아닌 음주 선택 | 함수 입력 오류 |
| 인원 증감 및 기능 끄기·켜기 | 위에서 정의한 선택 유지·초기화 규칙 적용 |
| 기능 꺼짐, 기존 쿼리 입력 | 기존 `splitBill` 결과와 화면 동작 유지 |

승인 후 구현 검증에서는 단위 테스트와 UI 입력 전환을 확인하고 `npm test`를 실행한다. 구현 전후 화면 증거는 동일한 120,000원 예시를 사용해 남긴다.

| 원 단위 잔액 | 대상자 번호순으로 1원 배분 / 지정한 사람이 전액 부담 | **각 비용별 번호순 1원 배분**. 입력을 늘리지 않고 총액을 맞추며 술값을 비음주자에게 넘기지 않는다. 번호가 빠른 사람이 최대 2원을 더 낼 수 있다는 점은 승인해야 한다. |
| 술값이 있는데 음주자가 0명인 경우 | 계산 차단 / 모두에게 분배 | **계산 차단**. 선택 누락을 알려 사용자 의도에 맞지 않는 술값 청구를 막는다. |
| 선택의 기본값과 초기화 | 모두 미선택 및 끌 때 초기화 / 전원 음주로 시작 / 끌 때 선택 보관 | **모두 미선택, 끌 때 초기화**, 인원 증감은 제품 스펙대로 처리. 음주 여부를 추측하지 않고 숨겨진 이전 값으로 계산되는 일을 줄인다. |
| 기존 균등 분배의 잔액 누락 처리 | 별도 작업 유지 / 이번 기능과 함께 수정 | **별도 작업 유지**. 현재 `splitBill`은 나머지를 버린다. 새 함수는 합계를 보존하되 기존 동작 수정은 별도 이슈와 검증으로 다룬다. |
| 구현 단계의 보호된 테스트 추가 | 사람이 테스트 추가 / 사람이 테스트 추가를 허용하도록 규칙 조정 | **사람이 위 검증 사례의 테스트를 추가**. 현재 하네스 기준을 유지하면서 구현의 성공 조건을 사람이 정할 수 있다. |

위 항목을 결정하고 스펙을 승인한 뒤 구현 이슈를 준비한다. 스펙 PR을 머지해도 이슈 #2는 닫지 않는다.
