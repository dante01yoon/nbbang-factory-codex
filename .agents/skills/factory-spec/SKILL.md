# 스펙 작성

사용자 메시지에서 이슈 번호를 읽는다(예: `$factory-spec 2`이면 2). 아래 `<번호>`는 그 값이다.

1. **격리 확인**: `pwd`와 `git branch --show-current`로 `.worktrees/issue-<번호>` 안의 `spec/issue-<번호>` 브랜치인지 본다. 아니면 아무것도 고치지 말고 "`scripts/factory spec <번호>`로 다시 시작해 주세요"라고 보고한다.
2. `specs/issue-<번호>.md`를 쓴다. 코드는 고치지 않는다.
   - **사용자 문제**: 이슈에서 사람이 하려는 일
   - **제품 스펙**: 화면에서 무엇을 입력하고 무엇이 보이는지. 예시 계산 한 개 이상
   - **기술 스펙**: 바뀔 함수와 데이터 모양, 추가할 테스트
   - **사람이 정할 것**: 에이전트가 임의로 정하면 안 되는 선택지. 항목마다 추천안과 이유
3. 커밋, push 후 draft PR을 연다. 본문은 AGENTS.md 형식을 따르되 첫 줄은 `Fixes` 대신 `Refs #<번호>`(스펙만 머지돼도 이슈가 닫히지 않게), `## Why`에 사용자 문제, `## How`에 "스펙 문서만 추가, 코드 변경 없음", `## AS IS / TO BE`에 지금 화면과 스펙대로 바뀔 화면을 글로 적는다. 이슈에 `needs-human` 라벨.
4. PR 주소와 "사람이 정할 것" 목록을 **한국어로** 보고하고 끝낸다.
